# Briefing generation

Reviewed against source September 29, 2026. The [MAIN pipeline trace](../../../docs/architecture/ai-pipeline.md#3-snapshot--complete-briefing) owns the full sequence and section table. [API readers](../../api/briefing/README.md) describe the saved-data routes.

[briefing-aggregator.js](briefing-aggregator.js) owns admission, short transactional generation claim, seven parallel `discover*` calls and final reconciliation. [briefing-generation.js](briefing-generation.js) fences writes by current run, snapshot, generation token and pending state. No provider operation holds the generation claim transaction open. Ordinary duplicates join existing pending work; another explicit Continue creates a fresh run/snapshot after failure. The old refresh-on-GET and partial-refresh descriptions no longer apply.

The [readiness contract](briefing-readiness.js) requires every section plus saved completion metadata. Weather has two columns, so seven sections occupy eight required fields. Explained successful empty lists are valid; failed providers, malformed fields and unknown airport coverage are not successful absence. Strategy re-reads this contract before dispatch. A 180-second join inactivity timeout fails rather than authorizing incomplete data.

Each [pipeline](pipelines/) owns its provider transformation. Raw `fetch*` functions and `discover*` persistence wrappers are deliberate layers (continuity memory 361). [briefing-notify.js](briefing-notify.js) uses [channel constants](briefing-channels.js) and generation-scoped writes; these progress events do not authorize Strategy. Schools run concurrently with the other six sections, with no cross-snapshot 24-hour success shortcut.

Airport conditions use FAA first following Melody's October 5 clarification. Concurrent US-airport lookups share one national NAS feed request. Only airports without usable FAA conditions enter a `BRIEFING_AIRPORT` conditions-search fallback; international airports use that research path too. An airport absent from the disruption feed is not verified normal. After conditions resolve, a separate `BRIEFING_AIRPORT` pass researches terminals, TSA waits, arrivals activity and pickup guidance using those fixed conditions. Its response cannot replace the saved status, advisory or `conditionsSource`. This is one Gemini stage when FAA supplies all conditions, or two when fallback is needed; healthy FAA conditions are never independently researched again. Failed fallback or terminal research still fails the section. The shared Airport formatter preserves source facts and uncertainty for Strategist and VenuePlanner. The [MAIN trace](../../../docs/architecture/ai-pipeline.md#3-snapshot--complete-briefing) records the source contract.

The five text-parsing pipelines use [shared JSON reconstruction](shared/safe-json-parse.js). It first parses the original text, then handles surrounding fences/citations and structural formatting without rewriting quoted values. Nested arrays and quoted brackets retain their original shape; a damaged or truncated envelope fails rather than publishing only the surviving records. September 30 regressions exercise the real helper and the airport pipeline. Gemini SDK text-part assembly precedes this helper; Holiday and Concierge have separate consumers and are not covered by this parser change.

[Event normalization/validation/storage](../events/pipeline/) is separate from [read reconciliation](../events/event-read-reconciliation.js). Read-time event freshness retains the two-hour post-event surge window. [cleanup-events.js](cleanup-events.js) resolves each stored venue's timezone before deactivation; missing or invalid timing remains evidence for repair. Deduplication must preserve distinct performances and conflicting source times. See the [review register](../../../docs/architecture/audits/PIPELINE_REVIEW_2026-09-29.md) for ongoing verification and fixes.

Events discovery retains two parallel category searches, HIGH thinking and Google Search. On October 5, the former 8,192-token cap returned `MAX_TOKENS` during a live search. The Events role now allows 32,768 tokens because [thinking and visible output share that cap](https://ai.google.dev/gemini-api/docs/generate-content/thinking); this is below the pinned model's [65,536-token output limit](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash). A subsequent live category completed with more than 8,192 thinking and output tokens, while its sibling reached the former 90-second deadline. Following an initial increase to 120 seconds, Melody requested three minutes so Events could finish. Each category and the Events role's router budget now allow 180 seconds; other model roles retain the 120-second router default. This does not guarantee completion: a failed or truncated category still fails Events before cached rows can be mistaken for completed discovery, and cancellation rejects late output. The adapter logs only numeric usage counts when truncation occurs.

The 180-second bound covers each parallel Events search, not the entire Briefing. Once a complete category arrives, Events verifies candidate content, schedules and venue identity and publishes eligible cards under `{items, _pending: true}` while the other search continues. Verification callbacks run serially outside the search deadline, with a separate 15-second venue limit per candidate. The final pass reuses verified results, applies the existing combined dedup rules and writes canonical events only after both searches complete. Later failure retains verified cards under `_generationFailed`; neither pending nor failed cards authorize Strategy.

Briefing display prioritizes supported high/medium-impact events within the established 15-mile nearby area, then supported high-impact wider-market draws. Distances are straight-line measurements from verified coordinates, not driving routes. Canonical event records and candidate counts are retained when display filtering excludes a result. Unknown impact and venue capacity do not establish a crowd or earnings. An empty selection explains that no verified high-value nearby events or major market crowd draws remained.

The cross-process Briefing join has a separate 180-second inactivity limit, renewed only by advancing persisted progress. It can still time out while the owner is running; it does not cancel the owner or admit incomplete context. The owner preparation request continues until reconciliation, while saved sections remain available through progressive reads.

[dump-last-briefing.js](dump-last-briefing.js) preserves the quiet diagnostic artifact requested in memory 218. The ignored file contains the caller's snapshot-scoped saved rows, written privately and atomically. It is explicitly not the exact Strategist request, and rows are read separately.

[tests/briefing](../../../tests/briefing/) covers completion, stored-source validation, provider failures, stale writers, progressive readers and retry behavior. Tests with mocked providers do not establish live API availability. The generation-token and MAIN-admission migrations must exist in the selected database before this code is deployed; this documentation does not claim they were run.
