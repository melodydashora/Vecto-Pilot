  ★ Insight ─────────────────────────────────────
  Three repo-specific choices worth knowing. The database is injected into the
  tool layer rather than imported, because server/db/connection-manager.js calls
  process.exit at import when DATABASE_URL is missing; that keeps the fail-loud
  runtime while letting 29 protocol-level tests run against a fake store. The
  memory status vocabulary is the union of the schema comment and what is
  actually in the table, since the live rows already carry done, pending, and
  resolved that the comment never mentions. And the separation from the bridge
  is structural, not just a comment: the new code imports nothing from
  server/agent, the gateway auth middleware, or the agent token helper.
  ─────────────────────────────────────────────────

  What shipped (all uncommitted, additive)
  - mcp-server.js at the root, with the modules under server/mcp/. It is a real
    Model Context Protocol server over the official SDK, on its own port and its
    own token, never mounted under /agent or proxied through 43717.
  - Tools cover the five continuity tables plus read-only repo access. Writes
    are insert or status-flip only, there is no delete, and app_rules has no
    write tool. Every write stamps the connecting client's name for provenance.
  - No shell, SQL, or file writes exist here by design. Those stay on the agent
    server.
  - The as-built doc is docs/architecture/mcp-server.md. Four stale docs that
    still described the removed 2025 "MCP" API as current were corrected.

  Verification
  - Full lint and typecheck clean, with the new entry file added to both lint
    globs.
  - All 29 new tests pass, including a real MCP client over an in-memory
    transport and the HTTP auth and session lifecycle.
